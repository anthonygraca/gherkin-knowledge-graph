# AS-07 — Honest provider availability and proposal provenance

**Issue:** [#29](https://github.com/anthonygraca/gherkin-knowledge-graph/issues/29) · **Parent:** F-07
[#13] · **Milestone:** M3 · **Owner:** C; A reviews provider semantics, B reviews problem shapes.
**Canonical criteria:** [AS-07.feature](AS-07.feature) (refinement draft, 6 scenarios).
**Status:** ready after specification review; depends on AS-06 for proposal history UI.

## Scope

Distinguish unregistered provider (400), registered-but-unavailable provider (typed 503), and a valid
empty result (200 with provenance). Show provider/model/index provenance for every proposal presentation;
label snapshot bindings as CTA bindings, not server index revisions; show missing historical provenance
as “not recorded”; document fake as the default offline path.

## Non-goals

Automatic provider fallback; model installation; provider health as assurance findings; acceptance
decisions.

## Verification plan (planned, not executed)

Deterministic provider transports plus real API problem documents; component/browser tests for panel
states and provenance labels; no live model required. SCN-3105 tests presentation of the adapter path,
not real inference.

## Contract impact

Optional problem extensions (`failed_provider`, `registered_providers`); MINOR schema bump if public;
UI-only changes otherwise. Independent review required.
