# AS-06 — Human decisions on version-bound proposals

**Issue:** [#28](https://github.com/anthonygraca/gherkin-knowledge-graph/issues/28) · **Parent:** F-07
[#13] · **Milestone:** M3 · **Owner:** C; B reviews the journal/domain, A reviews provenance.
**Canonical criteria:** [AS-06.feature](AS-06.feature) (refinement draft, 11 scenarios).
**Status:** needs owner design decision (trusted-local-operator identity). Not approved; not implemented.

## Scope

Explicit capture of a discovery candidate as a proposed link; append-only accept/reject decisions with
server-assigned operator, UTC time, reason, proposal snapshot, baseline and endpoint hashes; a review
workspace projection over immutable baselines; minimal review UI/history.

## Non-goals

Authentication service or multi-user roles; reversal/revocation; automatic acceptance; evidence or
finding mutation; Git writes; running assurance on acceptance.

## Design defaults (proposed, ADR 0012)

Trusted-local-operator mode; loopback review writes; append-only journal outside the fixture; workspace
read overlays decisions; only `proposed → accepted|rejected`; stale/conflicting/missing proposals are
typed errors. `TraceCandidate` keeps no link id or review state.

## Verification plan (planned, not executed)

API/persistence integration against temporary journals; restart recovery; conflicting writes; invalid
direction/endpoints; stale snapshots; baseline findings/evidence/thread and fixture file hashes unchanged
before/after. Browser checks for accept/reject/history. Existing pytest/Cucumber suites remain
independent regression gates.

## Contract impact

Additive endpoints, typed problem codes, workspace metadata; MINOR schema bump to `0.6.0`; update
`docs/domain-contracts.md` and regenerate fixtures. Owner disposition and independent acceptance review
are required before implementation.
