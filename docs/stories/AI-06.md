## User outcome

A developer can point an optional, bounded adapter at one pinned project snapshot and receive
source-code hits with exact paths, line ranges, content, scores as reported, provider identity, and
an honest index-identity marker. The adapter cannot accept links, change review state, or create
evidence, and the offline application never needs CocoIndex.

## Scope

* ADR 0008: adopt CocoIndex Code for AST-aware semantic code search; pin release 0.2.43; state
  license, CLI-vs-MCP choice, project-local index ownership, supported corpus, baseline isolation,
  and rollback.
* `backend/app/discovery/cocoindex.py`: typed request/hit/result models, error taxonomy, fake
  deterministic transport, and normalization client.
* `backend/app/discovery/cocoindex_mcp.py`: bounded MCP stdio transport that runs `ccc mcp` in the
  configured project root with an allow-listed environment and a hard deadline.
* `backend/app/settings.py`: `CTA_CCC_EXECUTABLE`, `CTA_CCC_PROJECT_ROOT`,
  `CTA_CCC_LIVE_OPT_IN`, `CTA_CCC_LIVE_TESTS`; default remains offline.
* `tools/probe_cocoindex.py`: opt-in capability diagnostic. Offline summary without `--live`;
  synthetic queries only; report outside the repository by default.
* Offline contract tests plus an opt-in live integration test.
* `docs/cocoindex-integration.md`: initialization, index, status, doctor, MCP search, isolation,
  probe instructions, and troubleshooting.
* Live smoke against an isolated worktree of `fixtures/banking-demo` at `baseline-a`, with observed
  hit paths/lines and recorded version/model/snapshot/index identity.

## Non-goals

* Registering a real discovery provider, mapping hits to `TraceCandidate`s, or changing
  `POST /api/discovery` (PR 2).
* Semantic indexing of `.feature` scenarios or requirements (CocoIndex Code's corpus is code and
  text files; scenario-aware chunking is not assumed).
* Chat inference, GraphRAG, M2 findings, UI work, deployment, or a second vector database.
* Closing AI-02/AI-03/AI-05. AI-02's "no request leaves the machine" criterion is not satisfied by
  an embedding runtime outside the executing machine; the external Ollama decision is recorded as a
  mission input, not as AI-02 completion.

## Preservation boundaries

* `FakeCandidateDiscovery` stays the only registered discovery provider; `GET /health` and
  `POST /api/discovery` are unchanged.
* No accepted link, review state, evidence record, assurance finding, fixture oracle, or
  hand-labeled expectation changes.
* No `SCHEMA_VERSION` bump: there is no request/response shape change.
* Default tests, CI, and application paths acquire no `ccc`, daemon, Ollama, network, Docker, GPU,
  or model-download dependency.
* CocoIndex's project-local index is a rebuildable external cache; the typed CTA store remains the
  system of record.

## Design impact

```text

backend/app/discovery/cocoindex_mcp.py   bounded MCP stdio transport (`ccc mcp`)

tools/probe_cocoindex.py                 opt-in capability diagnostic

docs/adr/0008-cocoindex-code-adoption.md decision record
docs/cocoindex-integration.md            operator/integration guide
```

The transport returns the documented structured MCP `search` payload; the client normalizes it and
rejects malformed paths/lines instead of repairing them. The result object has fields for provider,
query, limit/offset, hits, reported totals, server identity, configured project root, index
identity (or `None` = unavailable), and measured latency. No field can carry an accepted link,
review state, evidence id, or assurance conclusion.

## Refinement disposition

Derived from the RAG mission's PR 1 scope and the repository's F-08 story family. OMP authored the
first draft; an independent Codex `gpt-6.1-sol` (high) criteria advisory reviewed it **before**
implementation and returned REVISE. The frozen revision incorporates its major findings:

* configured project root is caller-supplied context, not observed index identity;
* index identity is explicitly unavailable over MCP;
* project selection/path validation is distinguished from a claim that all filesystem side effects
  are confined;
* the failure outline names exact error codes and bounded terminate/kill/reap behavior;
* malformed envelopes, incompatible server identity/schema, partial results on failure, and
  request/response bounds are explicit;
* live outcomes are split into no opt-in, unavailable prerequisite, execution failure, and
  attributable success; an offline skip never satisfies the live criterion;
* the smoke compares content with the snapshot under a declared rule and claims a bounded
  integration observation, not retrieval quality.

No human owner sign-off is recorded; this specification does not amend AI-01/AI-02/AI-03/AI-04/
AI-05.

## Known limitations

1. CocoIndex Code 0.2.43's MCP `search` result exposes path, language, content, line range, and
   score only. It does not expose an index revision, chunk hash, or project identity; those are
   reported as unavailable or attached from independently verified snapshot metadata.
2. The documented `include_patterns` do not include `.feature` files; scenario semantic search is
   out of scope for this story.
3. A live smoke proves capability at one synthetic snapshot and configuration, not general
   retrieval quality. Retrieval quality is AI-05's subject.
4. `ccc mcp` may start/restart a daemon and always schedules its own background index. CTA
   requires an isolated `COCOINDEX_CODE_DIR`/`COCOINDEX_CODE_RUNTIME_DIR` pair and refuses the
   default shared state; a session is not claimed to leave an index unchanged.
