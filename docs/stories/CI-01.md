# CI-01 — Assurance evaluates and reports the triggering revision

**Issue:** [#36](https://github.com/anthonygraca/gherkin-knowledge-graph/issues/36) · **Parent:** F-10
[#16] · **Milestone:** M4 · **Owner:** shared.
**Canonical criteria:** [CI-01.feature](CI-01.feature) (refinement draft, 6 scenarios).
**Status:** specification ready for review; implementation gated by the M3 exit and owner acceptance of
the two-scope framing (ADR 0012).

## Scope

Pinned evaluated revision (PR head/push after SHA), evaluator revision and input hashes in a typed
report; offline evaluation; report-only exit semantics (`0` completed, `2` tool failure); workflow
artifact/job summary; no branch writes.

## Non-goals

Deployment, generalized connectors, model inference, automatic remediation, generated-finding commits,
replacing existing test gates.

## Verification plan (planned, not executed)

Deterministic event fixtures for revision resolution; real offline ingestion/evaluation against temporary
repositories; corrupt report/I/O failures; hosted workflow run required to establish trigger/artifact
behavior (YAML inspection is not hosted evidence).
