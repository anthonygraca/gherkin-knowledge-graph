# CI-01 — Assurance evaluates and reports the triggering revision

**Issue:** [#36](https://github.com/anthonygraca/gherkin-knowledge-graph/issues/36) · **Parent:** F-10
[#16] · **Milestone:** M4 · **Owner:** shared.
**Canonical criteria:** [CI-01.feature](CI-01.feature) (draft, 6 scenarios; specification review
pending).
**Status:** specification APPROVED (`docs/reviews/CI-01-spec-review-4.md`); implementation in progress.
ADR 0012 §3 is accepted and the M3 gate is approved by `docs/reviews/M3-review-2.md`. Normative
report/comparison contract: [`docs/assurance-report-contract.md`](../assurance-report-contract.md).

## Scope

Pinned evaluated revision (PR head/push after SHA), evaluator revision and input hashes in a typed
report; offline evaluation; report-only exit semantics (`0` completed, `2` tool failure); workflow
artifact/job summary; no branch writes.

## Non-goals

Deployment, generalized connectors, model inference, automatic remediation, generated-finding commits,
replacing existing test gates.

## Verification plan (planned, not executed)

Deterministic event fixtures for revision resolution; real offline ingestion/evaluation against temporary
repositories; corrupt report/I/O failures; hosted workflow run required to establish trigger/artifact
behavior (YAML inspection is not hosted evidence).

## Specification review 1 disposition

The normative envelope, digest, input manifest, diagnostic transport, revision resolver,
self-assurance provenance, and workflow publication rules live in
[`docs/assurance-report-contract.md`](../assurance-report-contract.md). The feature now references it.

| Finding | Resolution |
|---|---|
| CI01-SPEC-R1 — report/manifest contract | Contract §1, §1.1, §1.2 fix the envelope, the revision-qualified input manifest, the full finding payload (including `status` and `artifact_revisions`), the digest serializer, and the oracle field comparison. |
| CI01-SPEC-R2 — revision execution and repository attribution | Contract §2 fixes the two-job matrix: self-assurance evaluates the CTA event head/after, while banking assurance evaluates the pinned baseline-b commit with the CTA event head as `evaluator_revision`; SCN-3402 requires end-to-end ingestion/evaluation. |
| CI01-SPEC-R3 — completeness vs availability | Contract §1.3 fixes the completed predicate, coverage counts, partial/skipped/unknown execution, absent evidence, and ingestion-diagnostic outcomes. |
| CI01-SPEC-R4 — diagnostic contract | Contract §1.4 defines the incomplete envelope, nullable unavailable inputs, failure stage/code, stderr fallback, and the prohibition on publishing a stale completed report. |
| CI01-SPEC-R5 — failed-test publication | Contract §5 requires `needs: [bdd]` + `if: always()`, completed `execution_failed` findings publication, preservation of the failing test gate, and separation of publisher failure from evaluator outcome. |
